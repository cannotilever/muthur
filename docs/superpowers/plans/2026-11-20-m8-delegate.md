# M8 Persona Delegation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** MU/TH/UR, in persona mode, can hand a self-contained task to the technical agent with a `delegate(task)` tool. The delegated work goes through every M7 gate, the operator sees one condensed line per command, and the report is either relayed by the persona or printed verbatim.

**Architecture:** The pure persona `agent::Turn` handles a `delegate` call by emitting `Effect::Delegate` and waiting. The MU/TH/UR tab then creates a child technical `Turn` (`Turn::delegated`). The child is driven by the same effect handlers that `/DIRECT` uses. A chat-log *lane* keeps the child's records apart from both `/DIRECT` and the persona. When the child finishes, the tab gives the persona `Turn` a `DelegateOutcome` through `on_delegate`. The persona's tool result is factual, a list of COMMANDS followed by the REPORT, and is built by the harness.

**Tech Stack:** Rust 2024, ratatui, serde/serde_json, tokio (in run.rs only). The existing test harnesses are in `src/agent/tests.rs`, `src/muthur/tests/agentic.rs`, `src/chatlog.rs` tests and `tests/golden.rs`.

**Spec:** `docs/superpowers/specs/2026-11-20-m8-delegate-design.md`

## Global Constraints

- Everything new that runs a command for a model sits behind `#[cfg(feature = "agent")]`. `cargo test --no-default-features` must pass after every task, and so must `cargo test`.
- `cargo clippy --all-targets` and `cargo clippy --all-targets --no-default-features` must stay warning-free.
- Officer label: `[agent] label`, default `SCIENCE OFFICER`.
- Config key: `[tools] delegate_report = "relayed" | "verbatim"`, default `"relayed"`. Any other value is a config error.
- Task validation: trimmed, non-empty, at most 4000 characters. Otherwise the result is `NOT AUTHORIZED: invalid task`.
- Exact screen copy: `DELEGATING TO <LABEL>`; `<LABEL>: <start line without RUN /RUN# prefix>`; `<LABEL> REPORTS:`.
- Exact tool-result copy: `COMMANDS:` / `NONE` / `REPORT:` / `REPORT (TRUNCATED):` / `NO RESPONSE FROM <LABEL>`.
- The persona prompt's tool lines must be exactly the four lines in Task 7. `{OFFICER}` is replaced with the label.
- The password stays in `Secret` and never reaches the chat log, the audit log, `tracing` or a model. The M7 rules are unchanged.
- No changes to M7 behaviour in `/DIRECT`. Every existing test passes unchanged, except for mechanical signature updates (`AgentId` → `Lane` in chat-log calls, the new `AgentDeps` field and the new `ToolsSection` field).
- Commit after each task. Messages use `feat:`/`fix:`/`docs:`/`test:` prefixes and end with the session's attribution trailer.

## Deviations from the spec (decided while planning)

- `DelegateOutcome` has no `Aborted` variant. On Ctrl-C, the tab aborts the child, then calls the persona's existing `Turn::abort()`. `abort()` resolves the waiting delegate slot as `ABORTED BY OPERATOR` and audits it with decision `aborted`. The behaviour is the one the spec describes.
- The delegate audit entry records its outcome through `decision` (`auto` for reported or no-response, `aborted` for Ctrl-C) and `output` (the tool result text, which starts with `COMMANDS:`). There is no separate `outcome` field.
- `report_mode` is stored on the delegated `user` record (`"report": "relayed" | "verbatim"`), not on the persona tool result. This keeps `ToolResult` unchanged.

## Review Focus

1. **A child LLM error or an unready technical config mid-delegation.** The persona turn must continue with `NO RESPONSE FROM <LABEL>`, not hang in `Tools` or end the whole inquiry. Test `delegate_child_error_gives_no_response` (Task 8) and `delegate_tech_not_ready_gives_no_response` (Task 8).
2. **A late tool outcome from an aborted child root command.** It must still be audited, with `delegated_by`, after the persona turn is gone. Test `ctrl_c_running_root_in_delegation_orphan_audited` (Task 9).
3. **`/DIRECT` after a delegation.** The tech window must not contain the delegated task or its tool rounds. Test `direct_window_skips_delegations` (Task 6), and `delegation_invisible_to_direct` (Task 8) end to end.
4. **Two delegate calls in one persona round.** They must run one after the other, each with a fresh child, and both results must reach the next persona request in call order. Test `two_delegations_in_one_round_run_sequentially` (Task 8).
5. **Restart after a crash mid-delegation.** This leaves delegated records with no persona `tool` record. Redisplay and the persona window must still load and not show a dangling delegation. Test `orphan_delegation_records_are_ignored` (Task 6).

**Behaviour, in one place:**
- `agent()` is `lane().agent()`.
- `llm_cfg()`, `defs()`, the policy choice in `stream_done`, `request_parts` (the tech system prompt and tech defs), and `tool_phase` (`EXECUTING`) treat "child present" like direct mode.
- `uppercase()` is false while a child is present, but only for child text, which is never shown anyway.
- **On `Effect::Delegate { call_id, task }`:**
  - If `self.tech.cfg.readiness()` fails, the tab calls `on_delegate(NoResponse { lines: vec![] })` straight away and applies the result.
  - Otherwise it:
    - pushes `Entry::Harness("DELEGATING TO <LABEL>")`;
    - calls `ensure_tech_system()`;
