# M9 Standby Screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After `[chrome] standby_minutes` without a key, MUTHUR shows a static Weyland-Yutani standby screen and writes nothing, so the WY-60's own screen saver can blank the CRT.

**Architecture:** A `standby` module shaped like `splash`. `App` holds `Option<Standby>` and renders it in place of the tabs; the backend's want/shown diff makes the unchanging frame cost zero bytes. Entry and prompt-wake are decided by `App::poll_standby`, called from the run loop beside `poll_settle`.

**Tech Stack:** Rust, ratatui, tokio, chrono; existing `Wy60Backend`, `StrictWriter`, golden harness in `tests/golden.rs`.

**Spec:** `docs/superpowers/specs/2026-11-20-m9-standby-design.md`

## Global Constraints

- Config key: `[chrome] standby_minutes`, `u32`, default `10`; `0` disables standby.
- Caption lines, exactly, each centred:
  `MU/TH/UR 6000 ── INTERFACE STANDBY` / `STANDBY SINCE <chrome::format_date(wall, offset)>` / `PRESS ANY KEY`
  (`offset` is `0` when the real-date toggle is on, else `year_offset`).
- While standby is active, nothing may reach the wire after the first standby frame.
- Wake keys are consumed: the whole batch is dropped; none reaches a tab or the prefix machine.
- Break keeps priority over everything (it ends standby and runs its usual handling).
- No test sleeps; time is injected (`handle_keys_at`, `poll_standby(now, wall)`).
- `App::new` / `ChromeView` stay unchanged: standby is opt-in via a builder, so existing goldens are untouched.
- Work on branch `m9-standby`. Commit messages end with the session's attribution lines.

## Review Focus

- A key batch that contains Break while asleep must reach Break handling, not be swallowed as a wake key — Task 4 `break_while_asleep_ends_standby_and_settles`.
- A key arriving between entering standby and the next render (prefix strip or help overlay open at entry) must not leave the strip/overlay drawn over the standby screen — Task 4 `entering_standby_closes_prefix_and_overlay`.
- A prompt that is already showing when the countdown expires must keep the TUI awake (the operator walked away mid-`CONFIRM`) — Task 5 `prompt_showing_blocks_standby`.
- Re-entering standby after a wake must restart the full countdown from the wake key, not fire on the next tick — Task 4 `wake_restarts_countdown`.
- The `STANDBY SINCE` time must not advance on later renders even though the wall clock does — Task 6 wire test asserts zero bytes with a changing clock.

### Task 4: App standby — enter, render, key wake, Break

**Files:**
- Modify: `src/app/mod.rs`
- Test: `src/app/tests.rs`

**Interfaces:**
- Consumes: Task 3 `Standby`.
- Produces on `App`:
  - `pub fn with_standby(self, after: std::time::Duration) -> Self` — enables standby (`App::new` has it off).
  - `pub fn poll_standby(&mut self, now: std::time::Instant, wall: chrono::NaiveDateTime)`
  - `pub fn standby_active(&self) -> bool`
- Private fields: `standby_after: Option<Duration>`, `last_key: Option<Instant>` (`None` until the first `poll_standby` or key batch; the first `poll_standby` sets it to `now`), `standby: Option<Standby>`.

Rules (from the spec):
- `poll_standby`: if `last_key` is `None`, set it to `now` and return. Enter standby when `standby_after` is `Some(d)`, `standby` is `None`, `now >= last_key + d`, no splash, `!passthrough`, `!settling()`, and `!self.awaiting_operator()` (Task 5 adds that check; in this task leave a private `fn awaiting_operator(&self) -> bool { false }`). Entering: `standby = Some(Standby::new(format_date(wall, offset)))` with the title bar's offset rule, `prefix = false`, `overlay = None`, `redraw = true`.
- `handle_keys_at(keys, now)`: Break check first (and `on_break` clears `standby`), then settling, then **if `standby` is `Some`: clear it, `redraw = true`, `last_key = Some(now)`, return**, then splash, then normal keys. Every batch that passes the Break/settling checks sets `last_key = Some(now)`.
- `handle_key(key)` routes to `handle_keys(vec![key])` when standby is active (as it does for Break/settling).
- `render`: when `standby` is `Some`, obscure every tab (`set_obscured(true)`), render the standby screen into `frame.area()`, return. Activity is still collected (`take_activity` → `self.activity`) so markers show on wake.
- `line_attrs`: standby's when active, else the splash's.
