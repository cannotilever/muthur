# M10 Self-Destruct Countdown Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From the Utility tab, arm a timed shutdown or reboot that takes over the screen with a Nostromo-style self-destruct countdown, a comic abort questionnaire, a secret freeze at `00001`, and a silent Esc abort.

**Architecture:** A pure `destruct` module (state machine, quiz, screen) shaped like `standby`/`splash`; `App` holds the running countdown and renders it in place of chrome and tabs. The Utility tab owns the arming prompts and hands a verified `DestructRequest` to `App`. Both `sudo` commands (verify, execute) go through one injected runner closure whose results come back as `Event::SudoDone`.

**Tech Stack:** Rust, ratatui, tokio, zeroize; existing `Wy60Backend`, `StrictWriter`, `ops::runner`, `ops::audit`, golden harness in `tests/golden.rs`.

**Spec:** `docs/superpowers/specs/2026-11-20-m10-destruct-design.md`

## Global Constraints

- Config: `[utility] destruct_seconds`, `u32`, default `60`; `Config::validate` rejects values outside `10..=5999`.
- Duration steps (seconds): `10, 30, 60, 120, 300, 600`, plus the configured value if absent, sorted; the configured value is the start.
- Verify argv: `sudo -S -k -p "" true`, 10 s timeout. Execute argv: `sudo -S -k -p "" systemctl poweroff` (or `reboot`), 30 s timeout. The password + `\n` goes on stdin only, built in a pre-sized `Zeroizing<String>` as `tools::shell::run` does.
- Counter: `ceil(remaining / 100 ms)` as five digits `MMSSt`; while running the X cycle is 3 s (see Task 4).
- Exact copy (all uppercase unless noted): `SHUTDOWN IN 01:00  <-/-> ADJUST  ENTER CONFIRM  ESC CANCEL`, `CLEARANCE REQUIRED -- SHUTDOWN IN 01:00 -- PASSWORD:`, `VERIFYING`, `CLEARANCE DENIED`, `AUDIT LOG OFFLINE`, `SELF-DESTRUCT ABORTED`, `UNABLE TO COMPLY -- <reason>`, heading `EMERGENCY DESTRUCT SYSTEM ── SHUTDOWN` / `── REBOOT`; quiz copy as in the spec table, verbatim (`troba` lowercase).
- Timings: arming delay `app::ARMING` (1 s); retort 1.5 s; freeze → `SELF-DESTRUCT ABORTED` after 1.5 s → Utility returns 4 s after that; countdown ticks every 100 ms.
- The password is zeroized: on Esc/cancel/denied at arming; on the first submitted quiz answer; on Esc/Break/freeze; right after it is written to the execute command's stdin. It never appears in argv, logs or audit.
- Esc abort and Break abort show nothing.
- `Secret` and `zeroize` stop being `agent`-only (`make check` builds both modes).
- No test sleeps; time is injected (`Instant` parameters, `now` closures).
- Branch `m10-destruct`. Commit messages end with the session's attribution lines.

## Review Focus

- An answer submitted inside the final 100 ms (or a late tick that lands past zero after an answer) must freeze, never execute — Task 3 `late_answer_still_freezes` and `late_tick_past_zero_freezes_if_answered`.
- A stalled loop that wakes long after zero with no answer must execute exactly once, not repeatedly — Task 3 `execute_emitted_once`.
- Switching tab, opening the prefix, or Esc while `VERIFYING` must leave nothing armed when the sudo result arrives — Task 6 `verify_result_after_cancel_is_ignored`.
- A countdown longer than `standby_minutes` must never fall into standby, and the standby countdown restarts when the destruct screen ends — Task 5 `standby_never_starts_during_countdown`.
- Break while frozen records `frozen`, not `aborted`; quitting mid-countdown records `aborted` exactly once — Task 5 `break_while_frozen_records_frozen` and `drop_mid_countdown_records_aborted`.

### Task 3: The countdown state machine

**Files:**
- Modify: `src/destruct/mod.rs` (tests in `src/destruct/tests.rs`)

**Interfaces:**
- Consumes: `Quiz` (Task 2), `Secret` (Task 1), `ops::runner::RunOutput`.
- Produces:
  ```rust
  #[derive(Clone, Copy, PartialEq, Eq, Debug)] pub enum Kind { Shutdown, Reboot }
  impl Kind { pub fn label(self) -> &'static str /* "SHUTDOWN"/"REBOOT" */; pub fn verb(self) -> &'static str /* "poweroff"/"reboot" */ }
  #[derive(Clone, Copy, PartialEq, Eq, Debug)] pub enum Outcome { Aborted, Frozen, Executed, Failed }
  pub enum Effect { Execute(Secret), Done(Outcome) }
  pub struct DestructRequest { pub kind: Kind, pub total: Duration, pub password: Secret }
  pub const TICK: Duration = Duration::from_millis(100);
  pub struct Destruct { .. }
  impl Destruct {
      pub fn new(req: DestructRequest, started: Instant, seed: u64) -> Destruct;
      pub fn preview(kind: Kind, total: Duration, started: Instant, seed: u64) -> Destruct; // never emits Execute
      pub fn kind(&self) -> Kind;
      pub fn tick(&mut self, now: Instant) -> Option<Effect>;
      pub fn key(&mut self, key: &Key, now: Instant) -> Option<Effect>;
      pub fn on_executed(&mut self, out: &RunOutput); // non-zero/timeout/not-found → Failed(reason)
      pub fn counter(&self, now: Instant) -> [u8; 5];   // digits M M S S t
      pub fn has_password(&self) -> bool;             // tests: zeroize points
      pub fn outcome_so_far(&self) -> Outcome;        // Running→Aborted, Frozen→Frozen, Executing→Executed, Failed→Failed
      pub fn quiz(&self) -> &Quiz;
  }
  ```
- Phases: `Running`, `Frozen { since: Instant }`, `Executing`, `Failed(String)`, plus preview's terminal `Zero` (counter `00000`, any key → `Done(Aborted)`).
- Rules:
  - `key`: Esc → `Done(Aborted)` in `Running`; `Done(Frozen)` in `Frozen`; any key → `Done(Failed)` in `Failed`; ignored in `Executing`. Other keys in `Running` go to the quiz; the first submission drops the password (`Option<Secret>` → `None`, zeroized on drop).
  - `tick` in `Running`: remaining ≤ 100 ms and an answer was ever submitted → `Frozen { since: now }` (counter holds `00001`); remaining == 0 and no answer → `Executing` and `Execute(password)` (once; preview → `Zero`, no effect).
  - `tick` in `Frozen`: `now ≥ since + 5.5 s` → `Done(Frozen)`.
  - Counter: `MM = tenths / 600`, `SS = (tenths / 10) % 60`, `t = tenths % 10`; frozen shows `[0,0,0,0,1]`; executing/zero/failed show zeros.
  - Failure reason: first non-empty line of stderr, else `EXIT <code>`; `TIMED OUT`; `NOT FOUND`; uppercased.

### Task 6: Arming on the Utility tab

**Files:**
- Modify: `src/utility/mod.rs`; create `src/utility/arm.rs` (the prompt state machine)
- Test: `src/utility/tests.rs`

**Interfaces:**
- Consumes: `SudoRun`, `sudo_argv`, `DestructRequest`, `Kind` (Tasks 3, 5); `app::ARMING`; `SharedAudit`.
- Produces: `pub struct UtilityDeps { pub run: SudoRun, pub now: Box<dyn Fn() -> Instant>, pub audit: SharedAudit, pub destruct_seconds: u32 }`; `UtilityTab::with_destruct(deps: UtilityDeps) -> UtilityTab` (`UtilityTab::new()` stays and ignores S/B); `Tab::take_destruct` and `Tab::on_sudo_done` implemented.
- States: `Idle`, `Duration { kind, idx }`, `Password { kind, secs, secret, drawn, armed_at }`, `Verifying { kind, secs, seq, secret }`, `Denied(&'static str)`.
  - `S`/`s`/`B`/`b` in `Idle` → `Duration` at the configured value; audit offline → `Denied("AUDIT LOG OFFLINE")`. ←/→ move through the step list (no wrap); Enter → `Password`; Esc → `Idle`.

  - `Denied`: the next key clears it (and is otherwise ignored).
  - `set_obscured(true)` in `Duration`, `Password` or `Verifying` → `Idle` (secret dropped; a later result is ignored).
  - Esc in `Verifying` → `Idle`.
  - Render: the strip on the tab area's last row, reverse video, full width: `{LABEL} IN {MM:SS}  <-/-> ADJUST  ENTER CONFIRM  ESC CANCEL`; `CLEARANCE REQUIRED -- {LABEL} IN {MM:SS} -- PASSWORD:` (no echo); `VERIFYING`; the denial text. `MM:SS` is minutes:seconds of `secs`.
  - `tick_interval`: `Some(100 ms)` while a prompt awaits arming, else `None`.
