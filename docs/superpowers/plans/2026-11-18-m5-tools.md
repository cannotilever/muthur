# M5 — MU/TH/UR Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** MU/TH/UR can call five read-only tools automatically. It can also ask to start, stop or restart allowlisted services; those run only after an on-screen `OVERRIDE REQUIRED — CONFIRM Y/N`. Both providers are supported, every call is audited, and tool rounds are stored in the chat log and replayed correctly.

**Architecture:**
- **`tools`** owns:
  - the registry, its definitions, and validation into a typed `Invocation`;
  - execution through an injected `Runner` (argv only, no shell);
  - the audit log.
- **`agent::Turn`** is a pure state machine. It turns stream endings, tool outcomes and Y/N answers into `Effect`s.
- **`MuthurTab`** carries out the effects:
  - spawning requests;
  - running tools on `spawn_blocking`, which come back as `Event::ToolDone`;
  - logging, auditing, transcript notes;
  - the `Override` prompt.
- **`chatlog`** stores `tool` records. It sends whole exchanges and drops past exchanges that never reached a final answer.
- **`llm`** serialises tools, `tool_choice`, assistant tool calls and tool results for both protocols.

**Tech Stack:** existing crates only. Commands run via `std::process::Command`, reusing the process-group, timeout and kill pattern from `metrics::probes::run_probe`.

**Spec:** `docs/superpowers/specs/2026-11-18-m5-tools-design.md`. Read it first; it holds the tool table, the error table and the window rules this plan refers to.

## Global Constraints
- **No shell.** Every command is an argv vector passed to `Command::new(argv[0]).args(&argv[1..])`, with stdin null. Nothing is ever interpolated into a shell string.
- **Unit names.** A name with no `.` gets `.service` appended. A valid name matches `^[A-Za-z0-9@._:-]+$`, is 1–128 characters, and does not start with `-`. Allowlists are compared after normalising.
- **Output cap.** Tool output is stdout followed by stderr, capped at 4096 bytes on a UTF-8 character boundary. When cut, `"\n[TRUNCATED]"` is appended.
- **Timeouts.** Tier 1 has 5 s, tier 2 has 30 s, and `max_rounds` defaults to 8. The override arming delay is 1 s.
- **Result texts are exact.** They are given in the spec's "Results and errors" table: `NOT AVAILABLE ON THIS SHIP`, `INSUFFICIENT CLEARANCE: …`, `NO RESPONSE`, `EXIT <n>: …`, `NOT AUTHORIZED: …`, `DENIED BY OPERATOR`, `ABORTED BY OPERATOR`, `TELEMETRY NOT YET AVAILABLE`, `COMPLETED: <VERB> <UNIT>`.
- **Stable tool definitions.** Order: `ship_status`, `service_status`, `journal`, `list_units`, `listening_ports`, `start_service`, `stop_service`, `restart_service`. A tier-2 tool whose allowlist is empty is left out. Each schema has `"additionalProperties": false` and every property listed in `required`.
- **Audit log.** `<state_dir>/muthur/audit.jsonl`, mode 0600, append-only. One record is written per call before the result goes to the model. While the audit log is offline, tier-2 calls are refused with `NOT AUTHORIZED: AUDIT LOG OFFLINE`.
- **Epoch hash.** `fnv64(format!("{provider:?}\n{model}\n{system}\n{tools_json}"))`.
- **No secrets in logs.** As in M4. The audit log is the only place tool output is written.
- **Screen.** All rendered text goes through `ascii_safe`. The golden test runs under `StrictWriter` with zero violations.

## Review Focus
1. **Hostile or garbled arguments from the model**, such as `unit: "nginx; rm -rf /"`, `"--help"`, `"../x"`, or 129 characters. The call is rejected with `NOT AUTHORIZED` and never executed (no argv is built). Test: Task 2 `rejects_hostile_units`.
2. **A type-ahead `y` arrives within 1 s of the override prompt appearing.** It must not confirm. Test: Task 8 `override_ignores_keys_during_arming`.
3. **vLLM emits a tool call whose arguments are not valid JSON** (the parser turns them into `{}`). The call fails validation with `NOT AUTHORIZED: missing unit`, and the loop continues to a final answer. Test: Task 2 `missing_required_argument_is_rejected` plus Task 5 `invalid_call_gets_result_and_loop_continues`.
4. **`systemctl restart` hangs.** It ends as `NO RESPONSE` after 30 s, and the UI stays responsive because tools run on `spawn_blocking`. Test: Task 3 `timeout_maps_to_no_response` plus Task 9 `tool_done_event_reaches_muthur`.
5. **The app is killed mid-chain**, after an assistant `tool_use` record but before its `tool` record. On restart that past exchange is left out, so no unpaired `tool_use` is ever sent. Test: Task 7 `past_exchange_ending_in_tool_use_is_excluded`.

// runner.rs
#[derive(Clone, Debug, PartialEq)]
pub enum RunOutput { Exited { code: i32, stdout: String, stderr: String }, NotFound, TimedOut }
pub trait Runner: Send + Sync { fn run(&self, argv: &[String], timeout: Duration) -> RunOutput; }
pub struct SystemRunner;  // process_group(0), stdin null, stdout+stderr drained on threads, killpg on timeout; spawn ErrorKind::NotFound → NotFound
// exec.rs
pub type SnapshotSlot = Arc<Mutex<Option<crate::metrics::Snapshot>>>;
#[derive(Clone)] pub struct ExecCtx { pub runner: Arc<dyn Runner>, pub snapshot: SnapshotSlot, pub elevate: Elevate }
#[derive(Clone, Debug, PartialEq)]
pub struct ToolOutcome { pub content: String, pub is_error: bool, pub argv: Option<Vec<String>>, pub exit: Option<serde_json::Value>, pub ms: u64 }
pub fn argv_for(inv: &Invocation, elevate: Elevate) -> Option<Vec<String>>;  // None for ShipStatus
pub fn execute(inv: &Invocation, ctx: &ExecCtx) -> ToolOutcome;
pub fn format_snapshot(s: &Snapshot) -> String;
pub const TIER1_TIMEOUT: Duration = Duration::from_secs(5);
pub const TIER2_TIMEOUT: Duration = Duration::from_secs(30);
```
- **argv** follows the spec's tool tables exactly. Tier 2 is `[elevate("sudo"|"doas"), "-n", "systemctl", verb, unit]`.
- **`exit`** is `json!(code)`, `json!("timeout")`, `json!("not_found")`, or `None` for `ShipStatus`.
- **Mapping**, per the spec's results table:
  - `Exited{0}` → content = cap(stdout + stderr), `is_error: false`. Tier 2 instead gives `COMPLETED: <VERB> <UNIT>`.
  - `service_status` with a non-zero exit and non-empty stdout → `is_error: false`.
  - A tier-2 non-zero exit whose stderr contains `password is required`, `not allowed`, `not permitted` or `not in the sudoers` (case-insensitive) → `INSUFFICIENT CLEARANCE: <first stderr line>`.
  - Any other non-zero exit with empty stdout → `EXIT <n>: <stderr trimmed>`. With non-empty stdout → stdout + stderr, `is_error: true`.
  - `NotFound` → `NOT AVAILABLE ON THIS SHIP`. `TimedOut` → `NO RESPONSE`.
- **`format_snapshot`** writes one fact per line, uppercase, reusing `metrics::{human_bytes, human_rate, human_uptime}`:
  - `HOST`, `UPTIME`, `LOAD`;
  - `CPU <n>%`;
  - `MEMORY <used>/<total>`, `SWAP …`;
  - `DISK <mount> <pct>%` for each disk;
  - `NET RX <rate> TX <rate>`;
  - `PROC <name> CPU <n>% MEM <bytes>` for each top process;
  - `FAILED UNITS <list>|NONE|N/A`;
  - `CONTAINERS <name status, …>|NONE|N/A`.

    Run { call_id: String, invocation: Invocation },
    Confirm { call_id: String, prompt: String },     // prompt = invocation.label()
    Note(String),                                     // "ACCESSING: <label>" | "ACCESS DENIED: <label or tool name>"
    LogTool(Vec<ToolResult>),                         // whole round, in call order
    Audit(AuditEntry),
    Finished { truncated: bool },
}
pub struct Turn { /* max_rounds, rounds, forced, pending calls with state + results */ }
impl Turn {
    pub fn new(max_rounds: u32) -> Self;
    pub fn on_done(&mut self, stop: &Stop, calls: Vec<Call>, defs: &ToolDefs, audit_online: bool) -> Vec<Effect>;
    pub fn on_tool_done(&mut self, call_id: &str, outcome: ToolOutcome) -> Vec<Effect>;
    pub fn on_confirm(&mut self, call_id: &str, yes: bool) -> Vec<Effect>;
    pub fn abort(&mut self) -> Vec<Effect>;
    pub fn awaiting_confirm(&self) -> Option<(&str, &str)>;   // (call_id, prompt)
    pub fn tools_running(&self) -> bool;
}
```
**Rules.** These follow the spec's "Agent loop" section exactly.
- **Each call resolves once**, with a `ToolResult { id, name, content, is_error, label }` and one `Audit` entry. The entry is emitted at the moment the call resolves, which is before `LogTool`/`Spawn`.
  - `Auto` and `Confirmed` entries carry the outcome's `argv`, `exit`, `ms` and content.
  - `Denied`, `Rejected` and `Aborted` entries have `argv`/`exit` set to `None`, `ms` 0, and `output` = the result text.
- **Order when a round finishes:** the last `Audit`, then `LogTool(round)`, then `Spawn { forced_final: rounds == max_rounds }`.
- **Audit offline:** with `audit_online == false`, tier-2 calls get `NOT AUTHORIZED: AUDIT LOG OFFLINE` and are `Rejected`.
- **`ToolUse` during a forced final:** the calls get `NOT AUTHORIZED: ROUND LIMIT` (`Rejected`), then `LogTool`. The first time this happens a forced `Spawn` follows; the second time it is `Finished { truncated: true }`.
- **Not a tool round:** any stop other than `ToolUse`, or `ToolUse` with no calls, gives `Finished { truncated: false }`.
- **`abort`:** every unresolved call gets `ABORTED BY OPERATOR` (`Aborted`). If the round has at least one call, `LogTool` follows. Then `Finished { truncated: false }`. With no open round, `abort` returns just `Finished`.
- **A `ToolOutcome` for an unknown or already-resolved call_id** is ignored and returns no effects.

- **Ctrl-C** in `Waiting`, `Streaming`, `Tools` or `Override`:
  1. abort any in-flight request;
  2. `apply(turn.abort())`, but skip its `Finished` effect;
  3. run the existing `end_early(None)`, which logs `interrupted` with the segment's partial text.
- **Errors** (`StreamEvent::Error`) mid-turn: `apply(turn.abort())` minus `Finished`, then `end_early(Some(e))`.

- **Redisplay:** for each `Exchange`, the user line, then one note per `tools` entry, then the reply as in M4. The note is `ACCESS DENIED: <label>` when the content starts with `NOT AUTHORIZED`, `DENIED` or `ABORTED`; otherwise `ACCESSING: <label>`.
